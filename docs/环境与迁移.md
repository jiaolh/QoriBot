# 环境管理、迁移与备份恢复

## 当前环境

| 组件 | 位置 | 版本 / 说明 |
|---|---|---|
| Node.js | runtime/node/node.exe | 24.19.0，Windows x64，含内置 SQLite |
| 包管理工具 | runtime/tools/pnpm | 11.19.0，仅安装 / 修复时使用 |
| QQ SDK | node_modules/@tencent-connect/qqbot-nodejs | 1.0.4，腾讯官方 |
| Anthropic SDK | node_modules/@anthropic-ai/sdk | 0.78.0，官方 SDK |
| 前端 | ui | 原生页面，不需要打包和编译 |
| 持久化 | data | JSON 配置 + SQLite 上下文与资料索引 + 用户 memory.md |

已安装依赖使用 hoisted 普通目录，启动时不依赖原电脑上的 pnpm 仓库、符号链接或全局 Node。运行环境版本和 Node.exe 的 SHA-256 记录在 runtime/manifest.json。

Windows 启动脚本优先使用内置 Node；若内置文件缺失，才尝试系统 Node 24 或更新版本。内置环境无需安装到系统目录。浏览器缓存、Windows 临时文件和系统本身由目标电脑管理，不属于本项目的可迁移数据。

## 整体迁移

1. 在“存储与环境”创建一次数据备份。
2. 点击左下角“退出程序”，等待服务结束。使用 console.cmd 时按 Ctrl+C，等窗口显示已退出。
3. 移动或复制整个 QQBot 文件夹。复制时包括隐藏的配置文件，不必保留可删除的 .cache。
4. 目标电脑使用 Windows x64；双击 start.cmd。
5. 若 QQ 平台启用了 IP 白名单，更新目标网络的公网出口 IP。确认 API 服务从目标网络可访问。
6. 在“运行概览”测试模型，再启动 QQ 机器人。

正常启动不需要安装依赖，只要 runtime 与 node_modules 齐全。模型对话和 QQ 接入仍需要联网。更换盘符、目录名称或带空格的路径无需修改配置。

已完成 35 项本地自动测试，并验证复制后更换为中文与空格路径的启动、配置、近期对话、长期 Markdown 资料和包管理工具。可使用内置 Node 运行 scripts/verify-portable.js 再次验证；它临时复制约 130 MB 环境到 .cache，完成后自动移除副本，全程使用虚拟凭证。

不要在程序运行时只复制 memory.sqlite，因为尚未合并的内容可能留在 WAL 文件中。完整退出后复制整个 data，或使用界面的备份功能。

如果迁往 Linux、macOS 或 Windows ARM，需要更换相应平台的 Node 与启动入口；目前提供并验证的便携环境是 Windows x64。

## 修复依赖

在项目目录打开 PowerShell，运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-dependencies.ps1
```

脚本优先使用项目内 pnpm、固定的 pnpm-lock.yaml，并禁用安装脚本。源码版缺少 runtime 时，使用系统 Node 24 或更新版本和 npx 临时调用 pnpm 11.19.0，参见 [GitHub 与源码安装](GitHub发布.md)。包仓库、下载元数据和包管理状态指定到 .cache；不会进行全局安装。

pnpm 11 使用 pnpm-workspace.yaml 设置 nodeLinker / storeDir / cacheDir，不能只依赖旧版 .npmrc。包管理状态目录由脚本的 --config.state-dir 指定。不要删除锁文件后随意安装最新依赖；如需升级，先备份，再更新明确的版本并重新验证。

runtime 缺失时：从 [Node 官方下载站](https://nodejs.org/dist/v24.19.0/) 获取 Windows x64 24.19.0 压缩包，把 node.exe 与 LICENSE 放回 runtime/node。内置 pnpm 若缺失，可从包注册表获取与清单一致的 pnpm 包，恢复 runtime/tools/pnpm。尽量保留整份 runtime，避免日常需要修复。

## 数据备份与恢复

“创建数据备份”将完整配置、一致的 SQLite 快照及 users 文件夹写入 backups/时间-标识。备份包括 API Key、QQ AppSecret、提示词、近期对话、长期资料和开关。

恢复步骤：

1. 退出程序。
2. 先将当前整个 data 保存到另一份安全副本，包括 users 和 SQLite 辅助文件。
3. 若退出后仍存在 memory.sqlite-wal、memory.sqlite-shm，将这两个文件一同移到当前数据的安全副本中，避免旧事务应用到恢复文件。
4. 移走当前 users 文件夹，再将备份中的 settings.json、memory.sqlite 和 users 复制到 data。旧版备份没有 users 时，数据库中的长期资料会在读取时重建文件。不要把旧 Markdown 文件混入恢复数据。
5. 双击 start.cmd，查看配置和记忆是否正确。

备份不会复制 Node、依赖、程序源码和界面；恢复到全新电脑时先复制完整项目，再恢复数据。导出 JSON 是查看用的单条会话副本，当前没有导入 JSON 恢复会话功能。导出的长期 Markdown 可复制到界面的资料编辑器保存。

## 性能与空间管理

默认近期轮数 10、过期 30 分钟、会话 1000、正文 32 MB；长期资料每人 4000 字符、总正文 8 MB、最多 1000 位用户；并发 4。小规模自用可把并发设为 1–2，把轮数设为 5–10。近期上限调整后直接应用已有历史；较早内容可能被移除，修改前可备份。长期资料不会过期或自动删旧用户。

数据库配置 2 MB 页面缓存；每次模型请求只读取当前会话，记忆不会全部加载到进程内。聊天日志仅保留最近 200 条状态，不持久化对话正文。模型输入输出和官方搜索次数的计数仅统计本次服务启动。

关闭管理网页可释放页面资源，后台服务继续接收 QQ。网页隐藏时暂停 5 秒状态轮询；未变化的日志、列表和占用条不会重复重建。目录大小最多每分钟更新一次，运行环境、依赖等固定目录在首次扫描后缓存，手动刷新会重新扫描。

自动整理最多占用一个模型并发位置，有 16 项队列上限。为减少 API 用量，可关闭全局或逐用户“自动整理”，使用 `/记住` 或手动编辑资料。服务内存包括 Node 的堆、网络缓冲和运行时预留空间；不会每次停止连接都立即归还所有预留内存。

安装缓存不影响运行，可在界面清理。删除正文后数据库文件未必立即变小，可用“压缩数据库”回收空闲空间。备份和导出不会自动过期，应自行按需要保留。

## 常见问题

| 问题 | 处理 |
|---|---|
| 打不开界面 | 查看 data/logs/error.log；尝试 console.cmd 查看启动错误 |
| 提示控制台已运行 | 访问 http://127.0.0.1:17860，避免重复启动 |
| 本地 17860 端口被其他程序占用 | 关闭占用程序或由开发者统一调整 server.js 与 run.ps1 中的端口 |
| 编辑 .env 不生效 | 正常行为：日常配置已改为 data/settings.json，请使用界面 |
| QQ 401 / 403 | 核对 AppID、AppSecret、平台权限和公网 IP 白名单 |
| QQ EACCES / EPERM | 退出旧服务，在 Windows 文件夹双击 start.cmd，避免继承受限运行环境；无需先关闭防火墙 |
| 连续点击连接后内存上升 | 观察堆内存与长期趋势；已加重试间隔和实例清理，具体验证见“排查与优化” |
| 模型 401 | 当前 API Key 错误、过期，或填到了另一家服务的配置 |
| 模型 404 | 检查 Base URL 与模型名称，查询当前 Key 可用的模型 |
| 群里不回复 | 需要 @机器人；检查测试群、机器人权限和界面运行状态 |
| 官方搜索失败 | 检查是否使用 DeepSeek 官方 Anthropic 预设、对应 Key 及账户授权 |
| 记忆清空后文件仍较大 | 退出正在生成的请求后，使用“压缩数据库” |
| 看不到以前的试聊记忆 | 旧版试聊不保存；新版“本机对话”会保存，QQ 用户资料需在该聊天场景中建立 |
| 修改 QQ 配置被拒绝 | 先停止机器人，再修改接收方式和凭证 |

不要同时运行后台控制台服务与独立的无界面机器人入口，避免同一 QQ 应用重复连接。console.cmd 运行的仍是完整控制台服务，用它时无需再双击 start.cmd。
