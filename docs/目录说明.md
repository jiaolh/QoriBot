# 目录说明

这是一个无需构建的 Windows x64 本地项目。程序使用相对于自身文件的路径定位工作目录，不依赖当前盘符、原来的绝对路径或 Codex 的运行环境。

GitHub 源码仓库只包含源码、界面、测试、维护脚本、文档和依赖清单。上图中的 `runtime/`、`node_modules/`、`data/`、`.env`、`backups/`、`exports/`、`.cache/` 是本机运行目录，由 `.gitignore` 排除；它们不需要随源码上传。使用系统 Node 的源码版可以没有 `runtime/`。

## 哪些内容可以清理

| 内容 | 清理影响 | 建议 |
|---|---|---|
| .cache | 不影响已安装依赖和当前数据，下次修复依赖可能需重新下载 | 在“存储与环境”清理；安装、更新和测试期间勿清理 |
| backups | 失去历史恢复点，不影响当前数据 | 确认不再需要后清理 |
| exports | 删除已导出的副本，不影响数据库 | 在退出程序后自行整理 |
| data/logs | 删除启动诊断输出，不影响记忆 | 退出后清理；下次启动会重建 |
| memory.sqlite | 删除全部记忆、备注与停用设置 | 使用界面管理，勿在运行时手动删除 |
| data/users | 长期资料的 Markdown 副本 | 删除文件会从数据库重建；清空资料请用界面或编辑正文 |
| settings.json | 删除密钥、提示词和全部设置 | 不应作为缓存清理 |
| runtime | 程序失去内置运行环境 | 迁移必须带走 |
| node_modules | 程序无法调用官方 SDK | 迁移必须带走；缺失时用维护脚本修复 |

项目空间统计包含主要运行目录、脚本、说明、测试、导出和根目录文件，不统计自行新增且未列入管理的目录。正文大小和数据库磁盘大小是不同指标：JSON 正文受容量上限限制，数据库还包含索引、用户标识和空闲页面。

## 配置与记忆的边界

日常配置的唯一保存位置是 `data/settings.json`。.env 只在该文件不存在时导入一次；后续编辑 .env 不会覆盖界面设置。命令行检查和试聊也读取同一份 settings.json。

会话按“私聊 / 群聊 + 目标标识 + 用户标识 + 提示词 ID”隔离。同一用户可能有多条会话。QQ 开放平台提供的标识不一定是 QQ 号，可在界面加备注。

长期资料按“聊天场景 + 目标标识 + 用户标识”隔离，不含提示词 ID，因此同一聊天场景的用户在切换提示词后仍可使用原资料。本机用户与 QQ 用户分别保存；同一 QQ 用户在不同群、私聊的资料不会互相注入。文件夹名是 24 位哈希标识，界面显示用户场景及备注。

近期对话的过期、轮数和清空操作不会删除长期资料。长期资料默认每位 4000 字符，总正文 8 MB，最多 1000 位用户；达到用户上限后，新的用户仍可聊天，暂不建立长期资料。降低上限不会自动删除已有长期资料；若正文超出新上限，设置会拒绝保存。文件副本与数据库都会占用磁盘，界面分别显示正文和项目实际占用。

“停用记忆”保留既有内容和设置，但不把历史带入模型，也不保存新回答。“清空正文”保留备注与开关；“删除会话”同时删除这些设置。过期仅清空正文；全局会话数或正文容量超过上限时，会移除最早活动的会话及其设置。

切换提示词不会删除旧记忆。修改同一套提示词会继续使用它原来的记忆；需要全新开始时新建提示词或清空对应会话。删除提示词后，它的旧记忆仍可在记忆页面清理。

密钥保存在配置文件与备份中，页面只显示是否已保存。复制整个项目时也会带走密钥和对话；分享代码时应排除 data、backups、exports 和 .env。
